# The files this repository and Glyndor/homebrew-tap carry as exact copies.
#
# scripts/monitoring/check-channel-drift.sh reads this file and compares every
# path listed here with the copy the tap publishes on its main branch. A listed
# path whose text differs, or that is missing on either side, fails the check.
#
# One path per line, relative to the repository root. Whole-line comments and
# blank lines are ignored. A path naming a file that one of the two
# repositories does not carry is a failure, not a skipped comparison: a list
# entry that cannot be compared is a hole in the contract, and a hole that
# reports green is how the copy stopped being a copy in the first place.
#
# WHAT BELONGS HERE
#
#   A file that is the same text in both repositories and has to stay the same
#   text: the shell both channels lint with, the CI policy both channels
#   publish under, and the tests both channels hold each other to. Thirty-two
#   files qualify today.
#
# WHAT DOES NOT BELONG HERE
#
#   The renderers under scripts/release/, which are two implementations of one
#   idea: they emit Ruby formulae in the tap and JSON manifests here.
#   check-render-drift.sh compares the units they share, and a byte
#   comparison of the files would be red forever.
#
#   scripts/monitoring/check-suite-on-main.sh, which has three different
#   implementations, one per channel, and is meant to.
#
#   The drift checkers themselves. Each names the repositories it reads, so
#   the same text in three places would be three wrong files.
#
# HOW TO ADD A PATH
#
#   Add the file to both repositories, make the two copies identical, and
#   then add the path here. A path added here before the tap carries the file
#   makes the check red, which is the check doing its job: the copies are
#   supposed to exist on both sides before anyone claims they agree.
#
#   This file is not listed in itself. It lives in this repository only, and
#   a path the sibling does not carry cannot be a shared copy.
